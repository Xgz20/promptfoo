# AStudio 单图评测用例维护

适用于本目录中的数据集、JSONL 和图片。完整操作步骤见 [产品维护指南](../../docs/astudio/datasets.md)。

## 新增用例

1. 阅读目标数据集的 README，确认版本与草稿状态。`astudio-v1` 用于产品用例，`examples-v1` 用于学习格式。
2. 查看用户提供的原图，确定一个短问题和可复核的评分规则，按任务需要提供参考答案。答案有歧义或缺少标注依据时，先向用户说明待确认信息。
3. 沿用目标集现有的 ID 字段和编号体系。新建数据集推荐使用稳定且唯一的 `sample_id`，如 `vision_chart_0001`，在 `vars` 和 `metadata` 中记录。
4. 将图片原始文件复制到目标数据集的 `images/`。示例使用 `vars.image` 和 `file://images/文件名`，已有数据集沿用与评测模板匹配的图片字段。文件路径基准与实际配置的 `basePath` 对齐，同一图片的多个问题可以引用同一文件。
5. 将一个完整对象序列化为一行，追加到目标 JSONL 文件。字段、参考答案类型和断言按目标集的说明及实际评测配置确定。示例提供可复用的填写方式。
6. 新建数据集推荐在 `metadata` 中记录 ID、场景、分类、能力、难度与版本。已有数据集沿用自身的维度体系，业务需要的维度可以扩展。
7. 从工程根目录运行 `node scripts/astudio/validate-dataset.mjs datasets/vision/<版本目录>`。校验成功后，再核对问题、图片、参考答案和评分规则是否一致。

## 维护约定

- 每条用例输入一张原图，输出文本答案。图片通过文件引用加载。
- 问题发送给被测模型，参考答案与评分规则提供给裁判。参考答案的依据应能在原图中核对。
- 根据实际评分需求选择 Promptfoo 断言，也可在评测配置的 `defaultTest` 中统一设置。示例展示 `llm-rubric` 的二值评分，产品可以使用其它断言类型、阈值和评分维度。
- 图片与用例一起纳入 Git。日志、模型回答、数据库和报告写入 `.local/`。
- 已冻结版本通过新版本目录演进，版本记录沿用目标集自身的约定。
- 默认校验检查通用结构、可识别的重复 ID 和本地文件引用。数据集专属要求通过 `--rules` 指定，文件引用基准目录通过 `--base-path` 指定。
- 用例维护的验收步骤是本地离线校验。调用模型属于评测执行阶段。
- 完成时给出新增/修改用例 ID、素材位置、标注依据、分类/能力分布和校验结果，便于产品复核。
